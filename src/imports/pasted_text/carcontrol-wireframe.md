Спроектируй каркас (wireframe/skeleton) веб-платформы CarControl — «цифровой гараж» для автовладельца. Это не разовый VIN-чекер, а постоянный личный кабинет, куда пользователь регулярно возвращается вести историю своего авто. Целевая аудитория — обычные автовладельцы в Казахстане, интерфейс должен быть простым для нетехнического пользователя, но выглядеть как современный SaaS-продукт (референсы по стилю: чистые дашборды в духе Linear/Notion/CARFAX Car Care/Drivvo — много воздуха, крупная типографика, карточки, минимум перегруженных таблиц на первом экране).

Сделай адаптивный дизайн: desktop-first дашборд, но с мобильной версией ключевых экранов (ввод записи голосом/фото — сценарий, которым чаще пользуются с телефона).

1. Общая архитектура (навигация)

Основные разделы (верхнее/боковое меню):

Дашборд — главный экран с общим состоянием всех авто пользователя
Мои авто — карточки/профили каждого автомобиля
Журнал/История — лента всех событий (ремонты, ТО, заправки, штрафы, страховка) по всем авто с фильтрами
Рекомендации — ИИ-советы по обслуживанию, ближайшие плановые работы
Отчёты — аналитика расходов, статистика по авто

Вспомогательные разделы: 6. Справочники — регламенты ТО по маркам/моделям, база проверенных СТО, база запчастей/расходников, каталог типовых работ и ориентировочных цен 7. Уведомления — центр уведомлений (напоминания, алерты, рекомендации) 8. Личный кабинет / Настройки — профиль, авто в собственности, подписка, интеграции (Telegram-бот, email, календарь) 9. Маркетплейс (заглушка под будущее развитие) — раздел-плейсхолдер: «скоро» для будущих сервисов (запись на СТО, аренда авто, зарядные станции для EV, подбор запчастей) — уже сейчас заложи для него пункт меню и общий шаблон карточки услуги, чтобы легко расширять

2. Экран «Дашборд» (главная после входа)
Верхний блок: приветствие + быстрая статистика по всем авто (общий пробег за месяц, потрачено на обслуживание за период, ближайшее плановое ТО с обратным отсчётом дней/км)
Карусель/сетка карточек авто — на каждой карточке: фото или 3D-превью авто, госномер, статус («всё в порядке» / «требует внимания» — цветовой индикатор), дата следующего ТО
Виджет «Рекомендации ИИ на сегодня» — 2–3 карточки с советами (например: «Пробег приближается к замене масла», «Скоро истекает техосмотр»)
Блок быстрых действий с крупными кнопками: «+ Добавить запись голосом», «+ Добавить запись по фото чека», «+ Вручную»
Мини-график расходов за последние 6 месяцев (line/bar chart)
3. Экран «Профиль автомобиля» — ключевой экран, продумай особенно подробно

Структура вкладок внутри профиля одного авто:

3.1 Визуализация состояния

Крупная область сверху: фото авто (загруженное пользователем) или переключаемая 3D-модель/схема кузова с интерактивными зонами (клик по капоту/двери/бамперу открывает историю повреждений/ремонтов именно этой части — референс на схемы кузова в отчётах об истории авто и на конфигураторы в духе автосалонов)
Переключатель вида: «Фото» / «Схема повреждений» / «Анимация 360°» (для будущего — не обязательно реализовывать сейчас, но заложи UI-переключатель)
Полоса-таймлайн под визуализацией: горизонтальная лента с точками — каждая точка это событие (ремонт, ТО, ДТП, покраска) с датой, при наведении — всплывающая карточка с деталями

3.2 Карточка «Здоровье авто»

Индикаторы по системам: двигатель, тормоза, шины/подвеска, кузов, электрика — каждый в виде прогресс-бара или светофора (зелёный/жёлтый/красный) на основе введённых данных и рекомендаций ИИ
Текущий пробег с возможностью быстрого обновления

3.3 История/журнал по этому авто

Лента записей в хронологическом порядке, каждая запись — карточка: тип (ремонт/ТО/заправка/мойка/штраф/страховка), дата, стоимость, миниатюра чека/фото, короткое описание
Фильтры по типу события и периоду
Кнопка «Добавить запись» с тремя способами ввода (см. раздел 4)

3.4 Документы

Хранилище: техпаспорт, страховка, диагностическая карта, сервисная книжка — загрузка фото/PDF, с датами окончания действия и напоминаниями
4. Экран/модальное окно «Добавить запись» — самая важная функциональная зона

Спроектируй как единый интерфейс с тремя способами ввода, переключаемыми табами или крупными иконками сверху:

Способ 1 — Голосовая запись

Крупная кнопка микрофона по центру, состояние записи (анимация волны/пульсации во время записи)
После записи — экран с автоматически распознанным текстом (заложи UI как будто это транскрипция голоса в текст), пользователь может отредактировать текст перед сохранением
Под текстом — блок «ИИ распознал» с автоматически предложенными полями: тип события, сумма, дата, категория — пользователь подтверждает или правит одним кликом

Способ 2 — Фото чека/документа

Область загрузки фото (drag&drop на десктопе, кнопка камеры на мобильном)
После загрузки — экран с превью фото и рядом — автоматически распознанные поля (сумма, дата, наименование СТО/магазина, состав работ) как будто это результат OCR-распознавания, с возможностью ручной правки
Индикатор уверенности распознавания (например, бейдж «Распознано автоматически» / «Проверьте вручную»)

Способ 3 — Ручной ввод

Простая форма: тип события (выпадающий список из справочника), дата, пробег, стоимость, СТО/место, комментарий, вложение фото

Внизу единая кнопка «Сохранить запись», после сохранения — короткая анимация подтверждения и обновление ленты истории и индикаторов здоровья авто.

5. Экран «Рекомендации»
Лента карточек-рекомендаций от ИИ, сгруппированных по срочности: «Срочно», «Скоро», «На будущее»
Каждая карточка: иконка типа работ, описание, обоснование («на основе пробега 45 000 км и записи о последней замене масла 8 месяцев назад»), кнопка «Записаться на СТО» (заглушка на будущий маркетплейс) и «Отложить»/«Выполнено»
6. Экран «Отчёты»
Верхние KPI-карточки: суммарные расходы за период, средний расход на 1000 км, количество событий
Графики: расходы по категориям (пирог/донат), динамика расходов по месяцам (line chart), сравнение периодов
Таблица истории с возможностью экспорта (в PDF/Excel — как минимум кнопка-заглушка)
7. Экран «Справочники»

Сделай в виде каталога с карточками-разделами:

Регламенты ТО по марке/модели (поиск по марке — выдаёт интервалы замены масла, фильтров, ремней и т.д.)
База проверенных СТО (карточки с рейтингом, специализацией, ценами — заглушка под будущий маркетплейс из раздела 1, пункт 9)
Справочник типовых работ и вилки цен по региону
FAQ/база знаний по обслуживанию авто
8. Личный кабинет / Настройки
Профиль пользователя, список авто в собственности (добавление нового авто через VIN/госномер)
Управление подпиской (бесплатный тариф с ограничениями vs расширенный)
Интеграции: подключение Telegram-бота для голосовых записей и уведомлений прямо из мессенджера, календарь (Google/Apple) для синхронизации напоминаний
Настройки уведомлений (какие события присылать, за сколько дней до дедлайна)
9. Сквозные ИИ-элементы, которые должны быть видны на нескольких экранах
Плавающая кнопка/иконка «Спросить ИИ-помощника» (чат-бот в углу экрана на всех страницах) — заложи как компонент, который открывает боковую панель чата
Единый визуальный язык для «ИИ-предположений» — везде, где система что-то распознала или порекомендовала сама (голос, фото, рекомендации), используй один и тот же акцентный цвет/иконку-звёздочку, чтобы пользователь визуально отличал «данные от ИИ» от «данные, введённые вручную»
10. Заложи расширяемость под будущие модули (не проектируй подробно, но оставь место в архитектуре)

В навигации и на дашборде должны быть места-заглушки под:

Карта зарядных станций для электромобилей (для владельцев EV)
Маркетплейс аренды авто в регионах
Онлайн-запись на СТО из справочника (сейчас справочник информационный, в будущем — с бронированием)
AI-оценка состояния кузова по фото (загрузка нескольких фото авто → автоматическая оценка повреждений) — уже сейчас предусмотри в профиле авто пункт «Оценить состояние по фото» как отдельную кнопку-заглушку с пометкой «скоро»
11. Общие технические/стилевые указания для Figma Make
Компонентный подход: карточка события, карточка рекомендации, карточка авто, индикатор-светофор, таб-переключатель способа ввода — сделай их переиспользуемыми компонентами с состояниями (default/hover/active)
Предусмотри пустые состояния (empty state) для нового пользователя без единой добавленной записи — с крупным CTA «Добавьте первую запись»
Состояния загрузки для экрана распознавания голоса/фото (skeleton-загрузка, спиннер)
Светлая тема как основная, цветовая палитра — нейтральная база (белый/серый) + один акцентный цвет для CTA и ИИ-элементов + светофорные цвета (зелёный/жёлтый/красный) только для индикаторов состояния
Иконки — простые линейные (в духе Lucide/Feather), без избыточной декоративности
